# Workflow prototype exploratory test

## Scope and setup

The test used commit `ba9d47a0eb3872287f37c5f5f3b49321393908ea` on 2026-10-28. The repository contains prototypes, not a production Narration Application. The [workflow prototype](../../prototypes/narrator-recording-workflow/README.md) uses in-memory test state. It does not import EPUB files, record audio, save Projects, or export files.

The test used a clean worktree, Python's HTTP server, and headless Chromium 136 through Playwright 1.52. The test tools and browser libraries were local to the worktree. The server used `127.0.0.1:18765`. The browser used a fresh page and no existing user data. The scripts use the visible buttons and labels. The [browser output](evidence/2026-ebook-browser.txt) and [journey script](evidence/2026-ebook-journey.js) record the actions and results.

## Journeys

1. **Start a Project and test the microphone.** New Project and Choose your EPUB file led to Your book is ready. Continue and Test microphone led to the test result. Try again returned to the microphone screen, and a second test led to recording. These are simulated actions. The Back variation failed as described below.
2. **Record and review.** Record, Pause, Resume, and Stop changed the displayed test state. Browse showed the first part as recorded and the other parts as not recorded. Review, Adjust the start or end, Done, and Record again returned to the first part. The test changed the start slider, but the prototype does not model audio or retain a slider value. No audio effect was verified.
3. **Finish and export.** The test recorded all three simulated parts, completed the three review screens, and reached Export complete. Reload returned to the initial state with zero saved parts. This matches the documented in-memory limit. No file was exported.

## Confirmed issue

[Issue 19](https://github.com/jonbaldie/ebook-narrator/issues/19) records a Back button that does not work. The Narrator cannot return to the book choice from Your book is ready.

Starting from a fresh page, select New Project, then Choose your EPUB file, then Back. The expected screen is Choose your book. The actual screen remains Your book is ready. Two fresh-page replays gave the same result. The [replay output](evidence/2026-ebook-back.txt) and [replay script](evidence/2026-ebook-back.js) record the result. The test searched all open and closed issues and read the prototype decision before filing. The repository did not have the documented `needs-triage` label, so the test created it and applied it to the issue.

## Unresolved observation

During a simulated recording, Next text changed the displayed part while the recording state remained active. Stop then marked the later part as recorded. Two fresh-page replays produced that result. The prototype has no real audio, and the agreed workflow does not specify the ownership of an active Take after navigation. This observation is not a confirmed production bug. [Issue 16](https://github.com/jonbaldie/ebook-narrator/issues/16) concerns Take ownership after a boundary change, not this navigation case.

## Blocked and not tested

The native audio prototype targets macOS and Windows. On this Linux host, `cargo run --locked --manifest-path prototypes/native-audio-wav-project-format/src-tauri/Cargo.toml --bin safe-diagnostics` failed because the GLib development package was not available. The [compiler output](evidence/2026-ebook-cargo.txt) records the failure. The Cargo cache, build output, and temporary directory were inside the worktree. No native audio, microphone, restart, or MP3 export result was obtained. The existing [native test results](../../prototypes/native-audio-wav-project-format/TEST-RESULTS.md) record the prior macOS tests and the decision to defer remaining device and Windows tests.

The workflow prototype has no real EPUB picker, microphone, audio playback, persistent Project, or export. These production journeys remain untested. The Back control gives no visible error when it fails. That makes the failed action difficult to distinguish from an unresponsive interface.
